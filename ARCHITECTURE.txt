================================================================
LSNB RÉSEAU - ARCHITECTURE DU PROJET
================================================================

Prototype du réseau des élèves et alumni du Lycée Scientifique
National de Bobo-Dioulasso (LSNB). Fonctions principales :
  - découvrir des parcours (spécialité, domaine, pays) ;
  - demander un échange / mentorat à un alumni volontaire ;
  - créer un profil (parcours, expériences, contact, photo) ;
  - rubrique « Highlights » : deux portraits d'alumni par semaine.


1. VUE D'ENSEMBLE
----------------------------------------------------------------

   Navigateur (React SPA)
        |
        |-- lecture/écriture directe (supabase-js, clé publique + RLS)
        |        --> Supabase : Auth, Postgres, Storage (photos)
        |
        '-- lecture publique des Highlights
                 --> API Node.js (Fastify) --> Supabase (clé secrète)

   Job planifié hebdomadaire (Render cron)
        --> génère les portraits (appel IA) --> Supabase

Aujourd'hui, l'interface parle directement à Supabase pour les
comptes, profils, photos et demandes de contact. L'API Fastify ne
sert que pour les Highlights et le contrôle de santé.


2. STACK TECHNIQUE
----------------------------------------------------------------
Frontend : React 19, TypeScript, Vite 7, Tailwind CSS 4,
           React Router 7, Anime.js (transitions), Three.js
           (cartographie de trajectoires du hero), lucide-react
Backend  : Node.js 24, Fastify 5 (+ helmet, cors), TypeScript
Données  : Supabase (Auth, Postgres avec RLS, Storage)
IA       : OpenAI (modèle gpt-5-nano) pour rédiger les Highlights,
           uniquement dans le job hebdomadaire
Hébergement : Render (site statique, service web, job cron)
Tests    : node:test + tsx, PGlite pour les tests de base de données

6. BASE DE DONNÉES (supabase/migrations/)
----------------------------------------------------------------
Migrations appliquées dans l'ordre :
  202609040001_initial_schema              profils, contacts,
                                           demandes, bucket photos
  202609050001_weekly_highlights           tables Highlights
  202609050002_google_auth_onboarding      complétion de profil
  202609050003_highlight_fallback_repair   réparation des secours
  202609050004_highlight_repair_retries    reprises
  202609150001_highlight_snapshot_gender   champ de sélection
  202610050001_profile_links               profiles.linkedin_url et
                                           profiles.portfolio_url
                                           (nullable, https:// exigé)
  202610050002_opportunities               offres, médias, signalements,
                                           bucket privé opportunity-media

Tables principales :
  profiles                 profils des membres (rôle alumni/élève),
                           dont liens facultatifs linkedin_url et
                           portfolio_url
  profile_contacts         coordonnées, séparées des profils
  connection_requests      demandes de contact / mentorat
                           (statuts : pending, accepted, declined)
  weekly_highlights        édition hebdomadaire
  highlight_articles       portraits publiés
  highlight_article_repairs  suivi des réparations
  opportunities            offres (bourse, stage, emploi, autre) ;
                           publiées immédiatement, lisibles par les
                           membres connectés uniquement
  opportunity_media        images (5 max, la 1re = couverture) et 1 PDF
  opportunity_reports      signalements ; 3 membres distincts masquent
                           l'offre (status = hidden)

Sécurité (Row Level Security) :
  - les profils actifs sont lisibles par les membres connectés ;
  - un membre ne modifie que son propre profil ;
  - les coordonnées ne sont lisibles que par leur propriétaire ou
    si celui-ci les a rendues visibles aux membres ;
  - les participants lisent leurs demandes ; le destinataire y
    répond, l'auteur peut retirer une demande en attente ;
  - photos : bucket public en lecture, écriture limitée au
    propriétaire (JPEG, PNG, WebP, 4 Mo maximum).

Offres : 5 publications / 24 h par membre ; liens https:// uniquement ;
fichiers dans le bucket privé opportunity-media (URL signées d'1 h) ;
l'auteur ne peut ni modifier une offre masquée ni la republier
(rétablir à la main : update public.opportunities set status =
'published' where id = '...').
Contact de l'auteur : réutilise connection_requests (kind = contact).

Fonctions SQL : claim_weekly_highlight, claim_ai_highlight,
save_highlight_article, publish_weekly_highlight,
complete_member_profile, claim/save/record des réparations.


7. FLUX IMPORTANTS
----------------------------------------------------------------
Inscription e-mail :
  /rejoindre -> Supabase Auth -> e-mail de confirmation ->
  /auth/callback -> session enregistrée -> /espace.
  La photo choisie est gardée 7 jours dans le navigateur puis
  envoyée après confirmation (même navigateur).

Connexion Google :
  /connexion -> Supabase Auth (Google) -> /auth/callback ->
  /completer-profil au premier accès -> /espace.

Highlights :
  Cron (lundi 00h00 UTC, reprise 00h20) -> sélection de deux
  alumni actifs (rotation, duo homme-femme privilégié) ->
  portraits rédigés par l'IA -> sauvegarde en base.
  Lecture : frontend -> API -> Supabase. Aucun appel IA au
  chargement des pages.
